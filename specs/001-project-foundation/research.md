# Phase 0 Research and Proposed Decisions

## ADR-001 — Workspace

**Status** — Approved by the project owner on 2026-11-26 for the two-member Phase 0 workspace.

**Decision** — Use native Dart Pub Workspaces with the two approved member paths. Commit the single root lockfile and enforce it in CI. Keep local caches untracked and declare compatible package versions explicitly.

**Alternatives and consequences** — Separate package resolution introduces separate lockfiles and makes the showcase integration harder to reproduce. Workspace-wide resolution makes incompatibilities visible early. Distribution to an external consumer remains a separate ADR-002 decision and relies on ADR-013 licensing approval. [Dart Pub Workspaces](https://dart.dev/tools/pub/workspaces), [lockfile enforcement](https://dart.dev/tools/pub/cmd/pub-get#enforce-lockfile).

## ADR-015 — Platforms

**Status** — Approved by the project owner on 2026-11-26 for Android and web in Phase 0.

**Decision** — Generate only Android and web showcase targets. Require an Android debug build, a web build and a manual launch on each target. Use the same expected output on both targets.

**Alternatives and consequences** — Automated device/browser launch jobs add orchestration beyond the approved foundation evidence. Later platform and production requirements retain their own acceptance gates.

## Phase 0 toolchain ADR

**Status** — Exact pins approved by the project owner on 2026-11-26. Clean builds and remote execution remain required for acceptance.

**Decision** — Pin stable Flutter 3.50.0 with bundled Dart 3.14.0 and use the package SDK constraint `^3.14.0`. Local Flutter metadata and direct execution of the bundled Dart binary confirm that pairing. Flutter's pinned Android template specifies Gradle 9.5.0 and AGP 9.3.1. Use API 36, Build Tools 36.0.0, NDK 28.2.13676358 and Eclipse Temurin 17.0.21+9. The AGP 9.3 compatibility matrix supports these component versions. Preserve the Kotlin configuration generated by the pinned Flutter template. [Flutter release notes](https://docs.flutter.dev/release/release-notes/release-notes-3.50.0), [AGP 9.3 compatibility](https://developer.android.com/build/releases/agp-9-3-0-release-notes), [Temurin 17.0.21+9](https://github.com/adoptium/temurin17-binaries/releases/tag/jdk-17.0.21%2B9).

**Runner** — Use the `ubuntu-24.04` label. The published runner inventory showed image `20261116.376.1` during research. GitHub rotates images behind hosted labels. Record the actual image version from the job log and explicitly provision the toolchain pins even when tools are preinstalled. [GitHub runner image inventory](https://github.com/actions/runner-images/blob/main/images/ubuntu/Ubuntu2404-Readme.md), [image release policy](https://github.com/actions/runner-images#image-releases).

**Alternatives and consequences** — Floating stable SDKs or `ubuntu-latest` increase drift. A self-hosted image would add operations outside the approved scope. The template and published compatibility evidence justify the proposed pins. Clean Android/web builds and remote CI are implementation acceptance evidence.

## Showcase capability and dependencies

**Decision** — Demonstrate trimming a display label with a single pure Dart function. Use a static fixture and an explicitly supplied home-screen value. Share lint policy and keep test dependencies local to the packages that need them.

**Alternatives and consequences** — A constant would demonstrate package resolution but offer no meaningful behavior to test. A result/error framework or state-management package would start later-phase work. Localised strings belong to the showcase and the core API remains independent of Flutter.
